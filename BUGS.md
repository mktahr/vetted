Aadhya P. has TWO `raw_ingest_events` (chrome_extension_voyager, both 2026-06-30) and EVERY experience row exists twice with identical values. Root cause confirmed by Codex code review: ingest's delete-then-reinsert of experiences ([lib/ingest/write-canonical.ts](lib/ingest/write-canonical.ts) — delete ~L461, row-by-row insert ~L575) runs with no transaction/lock and `person_experiences` has no role-identity unique constraint, so two near-concurrent ingests both delete then both insert → doubles. Also: one-off dedupe of Aadhya's existing rows (delete the older duplicate set). NOTE: the deterministic career-fallback layer (`lib/classification/career-fallback.ts`) already dedupes sources by `(title|company|start|end)` so inheritance dominance can't be faked by this bug. ~0.5 day.
